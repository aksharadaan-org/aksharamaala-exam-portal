FIRST DAY GUIDE

Start here

This site is the build guide for a separate exam app. You can learn the project from scratch, run the starter on your computer, and use the screen examples to build the rest.

What you are building: A student opens the Exam icon in the Aksharamaala app or an exam reminder. The separate Exam Portal opens. The student signs in, chooses qualities to practise, answers questions, submits, and sees results. The starter uses invented people and invented questions only.

What already works, and what you still need to build

PartTodayWhat that means for you
PostgreSQL databaseWorks locallyDocker starts PostgreSQL 17. The SQL files create tables and add sample data.
Student APIWorks locallyThe Node server handles demo sign-in, profile, qualities, stages, answers, submission, and progress.
Mobile appStarter onlyThe Expo app has one “Check mock sign-in” button. The student screens on this site are a browser preview of what to build.
Staff consoleDesign onlyThe browser preview demonstrates reports and editing. Staff API routes and a real staff app still need to be built.
Open from the main appFuture integrationThe route format is a design. It is not wired to the existing Aksharamaala app yet.

The four pieces in one picture

Phone appThe screens a student taps. It sends requests; it does not decide the score.
API serverChecks the student, saves answers, and calculates scores.
PostgreSQLStores students, questions, attempts, answers, and scores.
This guideShows the intended screens and rules. It does not contain live student data.

Example: tapping Save and continue makes the phone send an answer to the API. The API checks that this student owns the attempt, then saves the answer in PostgreSQL. The phone moves to the next question only after the API says “saved.”

Do this on your first day

  1. Read this page. Open Words explained whenever you see an unfamiliar term.
  2. Start the local system. Follow Run and update locally. The database and API run in separate processes.
  3. Try the browser previews. Open Student screens and go from Exam icon to result. Open Staff screens to see the future staff experience. These previews simulate data in your browser; they do not call the API.
  4. Read one complete example. Follow the step-by-step flows and see which API call each button needs.
  5. Build and verify one small change. Run npm run verify at the repo root. Use How to check your work for behavior tests.

A sample student journey

Student seesWhat happens behind the screenSaved where?
Sign in as demo-a, enter 246810The API creates a short-lived challenge, checks the code, and returns a session token.Demo sign-in state lives in the API server's memory.
Choose qualitiesThe app loads 24 sample qualities and saves the chosen IDs.exam.selections in PostgreSQL.
Start BaselineThe API creates one attempt for this student and stage and fixes its question list.exam.attempts and exam.items.
Choose an answerThe API saves one choice. The student can leave and resume.exam.items.choice.
SubmitThe API checks every question is answered and calculates the result.exam.scores and the submission time.
See progressThe app reads earlier submitted results.Results are read from PostgreSQL through the API.

The demo code is for local testing only. The real sign-in provider and live student records are outside this starter.

Where should I look in the repository?

Folder or filePlain meaning
