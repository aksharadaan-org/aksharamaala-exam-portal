Verification & handoff

Run npm test for the starter contract. Use the scenarios below as release evidence for the implemented app. Record fixture, build, OS, expected outcome, observed outcome and the reviewer.

How to use this checklist

For each row, perform the action in the app you are building and compare it with the pass condition. The starter's npm test checks backend behavior. It does not prove that the new mobile screens, staff console, or app launch link are finished.

Write down which build and demo account you used, what you expected, what actually happened, and any screenshot or error. Fix failed behavior before calling that feature complete.

Example: Save an answer, close the app, and reopen it. The same answer should appear. If it disappears, the app may have shown an unsaved choice as if it were saved.

Owner inputs before pilot

Confirm the named qualities and dimensions, translations, approved questions, feedback bands, OTP provider, consent and retention, official stage dates and retakes, school transfer and reporting scope. Interns use the documented fixture defaults while these decisions are pending. Each changed rule requires a fixture, contract revision if applicable, and regression case.
