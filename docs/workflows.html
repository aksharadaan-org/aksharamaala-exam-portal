Workflow specifications

Trace each interaction from its entry condition through its service writes and recovery path. Screen designs are available in the student app and staff console chapters.

Sign in and restore
Entry
Host tile, warm notification or direct open
Interaction
Parse only the documented stage route. Wait for secure storage, then GET /me. Without a usable session, request a challenge and verify the six-digit mock code. Preserve a single pending stage through sign-in.
Service and storage
Store bearer on success. Issue a new challenge after expiry. On sign-out revoke bearer, clear secure storage and pending navigation.
Alternate path
Wrong code → inline error. Expired bearer → return to sign-in. No installed app → install fallback.
Profile and quality selection
Entry
First setup or learner edits
Interaction
Validate name, grade, school and locale. Derive district from school. Group qualities by four dimensions, allow multiple selections and require one to proceed.
Service and storage
PATCH /me with the full profile. PUT /selections is additive. Existing attempt items stay fixed when the learner adds a quality.
Alternate path
Keep form inputs if validation or network fails. Move focus to first invalid field.
Stage list and due state
Entry
Profile complete or returning login
Interaction
Draw baseline + practice 1–4. Read /stages; prefer a stored submitted result, then time window, prerequisite, and draft status. Show start, resume or result action.
Service and storage
POST /attempts with stage. Unique student + stage returns same ID on double tap. Attach question versions for selected qualities at creation.
Alternate path
At close exactly: reject answer writes/first submit. Completed result remains readable. No quality → open selector.
Runner and draft
Entry
Start or resume stage
Interaction
GET attempt. Traverse items in stable order, restoring saved choices. Allow changing earlier answers during review. Disable next while saving; retain unsaved choice on failure.
Service and storage
PUT one {question,choice}. Acknowledgement enables navigation. Reopen at first unanswered item or review if complete.
Alternate path
If connection fails after sending a write, fetch current attempt. Retry the same answer if unacknowledged.
Review and score
Entry
All items answered
Interaction
List questions with Edit actions. Confirm submit once, disable the button while pending. Aggregate counts by quality.
Service and storage
Submit transaction checks owner, completeness and window, writes scores and timestamp together. Result uses immutable score rows.
Alternate path
409 incomplete → reload review; 409 closed → show state. Lost success response → GET attempt before retry.
Progress and report
Entry
Completed or returning learner
Interaction
Show stage/date, raw fraction, percentage and feedback; expand a stage for per-quality detail. Compare the same quality only when both stages have results.
Service and storage
GET /progress; submitted attempts only in trend. Round only for display. Sum raw earned/possible for stage score.
Alternate path
Empty → offer baseline. Newly added quality → no historical value. Zero denominator → dash.
School roster and registration
Entry
Staff selects school
Interaction
List synthetic roster by school and district. Administrator adds a school, assigns learner profile, validates grade and retrieves saved row. School viewer is read-only.
Service and storage
Server derives allowed scopes from session. Freeze stage cohort at opening for historical analytics.
Alternate path
403 for scope mismatch; conflict on stale edit; no matching learners → empty roster.
Question authoring and publication
Entry
Administrator edits a quality
Interaction
Create draft, provide two translations, translated options, one correct index and scoring version. Preview both locales, then explicitly publish.
Service and storage
Create new immutable published version. Link new attempts to latest version. Retain historical question IDs and score snapshots.
Alternate path
Missing translation or key → 422. Editing after preview → 409, reload the draft.
Schedule a practice window
Entry
Administrator opens stage editor
Interaction
Choose a single stage. Enter opens/closes in UTC, preview the interval, save with revision. Display local time on the student screen.
Service and storage
Update stage window only. Reads remain available after close. Apply server time on each submission and answer save.
Alternate path
Reversed dates → inline error. Stale revision → reload schedule before saving.
Monitor and export
Entry
School viewer or programme administrator
Interaction
Filter eligible cohort by district, school, stage and time range. Show denominator and numerator for participation/completion. Rank quality selections, submitted practice and matched improvement.
Service and storage
Both report endpoints share scoped query and filters. Aggregate CSV uses UTF-8, escapes fields, neutralizes formula-leading user text.
Alternate path
Zero matches → header-only export; zero denominator → dash. School viewer cannot widen scope.
Merge and refresh
Entry
Approved SQL or fixture change reaches main
Interaction
Read the refresh chapter for exact commands, branch collision handling and backup procedure.
Service and storage
A fresh checkout and an existing populated checkout converge on matching schema versions. Existing attempts remain local.
Alternate path
Checksum mismatch, missing migration or foreign-key error stops the migration transaction.

Native layout and accessibility

Use a single column on phones with a persistent stage title, answered count, choice group and primary action. Preserve safe-area spacing around the keyboard. Give touch controls at least 48 logical pixels, support large text and announce save errors. Restore focus to the edited item when returning from review. Label radio choices with their selected state. Use translated text alongside color for locked, draft and completed stages. The staff console uses a filter bar, metric cards and a horizontally scrollable table on small screens.
