Launch, identity & integration

The host supplies an assessment destination. The exam app owns sign-in, student authorization and the attempt. A route is a request to navigate.

What each box means

Host: the existing Aksharamaala app will eventually have an Exam icon or reminder. Exam app: a separate app that shows the exam screens. API: the server that checks sign-in and exam rules. PostgreSQL: the local database that stores sample records.

Future connection Opening the exam app from the host is a design in this guide. It is not connected to the existing app today. Interns can test the same entry idea inside the standalone app with a sample stage link.

Example: A reminder asks for Practice 1. The app remembers “Practice 1,” asks the student to sign in if needed, checks that Baseline is complete, then opens Practice 1. The link itself must not contain a student ID or token.

Future merge rehearsal

The mobile shell owns route decoding and the exam feature entry. The service adapter keeps networking outside screens. An integration harness mounts the entry in a second blank shell, injects a fake session and exercises start, logout, resume and exit. Later, the platform owner implements server-side identity mapping and contract adapters, validates staging with internally managed accounts and enables the host tile behind a feature flag. Roll back the flag independently of stored attempts. Synthetic IDs are disposable and must never identify real students.
