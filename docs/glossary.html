Words explained

A quick dictionary for this project. The examples use the invented learner demo-a.

App / mobile client

The screens running on the student's phone. Here it is built with Expo and React Native.

API / backend

The server the app talks to. The app asks it to sign in, save answers, or return a result. It enforces the rules.

Endpoint / route

One API address for one action. For example, GET /v1/qualities asks for the qualities list.

Request / response

A request is what the app sends to the API. A response is what the API sends back. A response may contain data or an error.

GET, POST, PUT, PATCH, DELETE

Request types: read; create or perform an action; replace/save; change part; remove or sign out. The route and type together identify the action.

JSON

A common format for sending data, such as {"stage":0}. Stage 0 means Baseline.

Session token / bearer

A temporary secret the API gives the app after sign-in. The app sends it with later requests so the API knows which demo learner is calling.

Database / PostgreSQL

Software that keeps records after the API is stopped. This project runs PostgreSQL version 17 locally.

Table / row / column

A table holds one kind of record. A row is one record; a column is one field. exam.attempts is the table; a single exam try is a row.

Schema

A named group of tables inside a database. The app's tables are in the exam schema.

Migration

A numbered SQL file that changes the database structure or sample data. Each teammate applies new migrations after pulling changes.

Fixture / seed data

Invented records used for local work: two demo students, schools, qualities, and questions. They are safe to rebuild.

Docker / Compose / volume

Docker runs PostgreSQL in a container. Compose starts it from compose.yaml. A volume keeps its data when the container stops.

Attempt / draft / submission

An attempt is one student's try at one stage. It is a draft while answers can change. Submission locks it and stores the result.

Stage / Baseline

A stage is one exam round. Stage 0 is Baseline; stages 1–4 are Practice 1–4. The previous stage must be submitted first.

Quality / dimension

A quality is a sample skill or behavior the student chooses to practise. The 24 sample qualities are grouped under four dimensions.

Snapshot / question version

When an attempt starts, the API fixes its question IDs. Later changes to selections or questions do not rewrite that attempt.

Mock / prototype

A mock is invented behavior for development. The browser screen previews are prototypes; they keep state in the browser and do not call the real local API.

UTC / time window

UTC is the common time reference stored by the server. A stage opens at its start time and closes at its end time. The closing instant is already closed.

Git branch / PR / CI

A branch holds proposed code changes. A pull request (PR) asks for review before merging. CI runs checks automatically on the PR.

RLS

Row-level security: PostgreSQL rules that stop one student from reading or editing another student's records.

Deep link

A link that opens a specific screen in an app, such as a particular exam stage. This is a future integration design here.
