Student and staff contracts

All routes below use /v1. The local student reference returns HTTP 200 on success and JSON errors shaped as {"error":"code"}. Protected routes take Authorization: Bearer <token>. The request examples use invented IDs.

Staff service design

These endpoints describe the target staff implementation. School viewers have one school scope. Programme administrators can edit published content through versioned drafts. Resolve scope from the server session before applying query filters. The local student service currently accepts student sessions only.

EndpointBody or queryRequired behavior
GET /v1/staff/schools · GET /v1/staff/studentsschool, district, cursor, limit (default 50, max 100)Return {items,nextCursor}, ordered by ID. 403 for a scope outside the session.
POST /v1/staff/schools · POST /v1/staff/students{label,district} or {name,grade,school,locale}Administrator only. Validate school references and locale. Return 201 with generated ID.
PATCH /v1/staff/students/{id}Changed fields + revisionValidate writable fields, update roster for future windows. Preserve a snapshot for historical reports. 409 on stale revision.
POST /v1/staff/items{quality,en,te,options:[{en,te}],correctIndex,scoringVersion}Validate both translations and one valid key, return 201 draft ID and revision. Keep the key in the admin representation.
POST /v1/staff/items/{id}/publish{revision}Mark draft published, supersede previous version for future attempts, retain old version for history. 409 if already published or edited since preview.
PUT /v1/staff/stages/{stage}{openAt,closeAt,revision}ISO UTC timestamps; openAt < closeAt. Reject invalid intervals with 422, stale revision with 409.
GET /v1/staff/report · GET /v1/staff/report.csvstage,school,district,from,toAuthorize scope. Aggregate the same population for JSON and CSV. Return counts, per-quality totals and matched change. CSV uses UTF-8 and a header even when empty.
